# Shot-aware cast bindings

Advanced preparation supports three persistent cast IDs. Each subject may have ordered, non-overlapping `intervals` with integer `start` and exclusive `end` frames relative to the normalized 24 fps clip. Different subjects may overlap during camera transitions. An empty interval list retains the legacy whole-clip track.

Each visible span requires a point or box anchor inside it; the anchor need not be its first frame. SAM 2.1 initializes a fresh state per subject and span. The earliest annotated frame seeds the person by default. Optional subject `seed_frame` selects a better visible anchor in its containing span; other spans retain their earliest anchor. The worker tracks forward and backward before applying all other annotations, including earlier frames, as corrections with tracked context. Corrected frames remain conditioning frames during final propagation in both directions. Same-frame point/box entries merge, with conflicting boxes rejected. SAM input counts, output indices and returned subject IDs must match the span. Corrections belong to that span. SAM 3 does not support interval, visibility or seed selection; mesh modes retain their single-subject limit.

Select the visible person, including head/hair, neck, body and visible limbs, with a suitable box and positive points. Negative points exclude specific background or another person. A torso click alone can select clothing; the model does not infer a whole-person requirement from the application's subject name. No boxes, anatomical points or mask dilation are generated automatically. The seed and correction outputs still require review. Mask cache version 5 includes visibility and seed selection and prevents reuse of masks produced with the former global gap/overwrite behavior. Existing versions 3 and 4 remain available as evidence.

Optional subject `visibility: [{start,end,state,reason}]` declares source-reviewed absence or occlusion inside existing cast intervals. Notes must be ordered, non-overlapping and contained in an interval, with a nonblank evidence reason. `absent` and `fully_occluded` exclude frames from inference and split propagation state; reappearance needs a new anchor. `partially_occluded` still requires visible foreground and never exempts missing masks. Output stays zero outside visible spans. No shot or visibility guesses are inferred automatically.

The legacy `allow_empty_frames` field remains readable but no longer exempts an unexplained active-subject gap. Presence is checked for each cast ID; another subject cannot hide a gap. Frames outside all configured cast intervals are reported separately as unassigned, not claimed to have no physical person. A correction atomically replaces only its own label. Predicted overlap with another ID fails with frame, IDs and pixel count before either label is changed; annotation review must resolve the ambiguity. Overlapping cast intervals with disjoint visible pixels remain supported and order-independent.

The local `tracking` JSON records cast intervals, visible spans, visibility reasons, per-subject missing frames, globally empty frames and unassigned frames. Review source, labels and conditioning together. Recipe edits invalidate approval; mask keys include annotations, intervals, visibility and seed selection while unaffected audio/depth can be reused. This is a tracking presence/identity check, not the full appearance/anatomical preparation gate planned for Step 4.

The studio provides numeric interval controls and correction anchors, including keyboard alternatives. Cast images, annotations, tracking reports, and real test clips remain private runtime data.

Mask labels are atomically saved as uncompressed uint8 NPY arrays and memory-mapped during compositing. A local multi-frame round-trip reproduced CRC failures in compressed NPZ mask storage; uncompressed storage avoids that compression path. An 18-second 540×960 mask uses approximately 224 MB. Valid legacy NPZ masks remain readable, but the new mask cache version prevents reuse of older affected outputs. Hash checks still protect immutable cached artifacts.
